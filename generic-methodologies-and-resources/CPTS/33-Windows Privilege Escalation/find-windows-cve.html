Windows Privilege Escalation — Recon & Research Guide

build 17763.6893
Beginner Friendly

From zero shell access to finding PrivEsc exploits

One command to gather all system info, how to read the output, and exactly where and how to search for CVEs and proof-of-concept exploits.

1

The one command you need

Run this in PowerShell on the target
Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion' |
  Select ProductName, CurrentBuild, UBR, ReleaseId
Example output
ProductName                   CurrentBuild   UBR    ReleaseId
-----------                   ------------   ---    ---------
Windows Server 2019 Standard  17763          6893   1809
ⓘ These 4 values are everything you need to identify the system, find its patch date, and search for unpatched vulnerabilities.
2

Understanding the output — what each field means

Field Your value What it means & how to use it
ProductName Windows Server 2019 Standard The exact product name. Use this when searching CVE databases. Search for "Windows Server 2019" — not just "Windows". Being specific gives you results that actually apply to your system.
CurrentBuild 17763 The kernel build number. This identifies the OS release (not the patch level). Windows 10 version 1809 AND Windows Server 2019 both share build 17763. This means kernel-level exploits affect BOTH. Always search CVEs for both product names when using this number.
UBR 6893 Update Build Revision — the most important number. Combined with CurrentBuild, your full patch level is 17763.6893. Higher UBR = more patches installed. You are vulnerable to any CVE patched in a UBR higher than yours. UBR of 1 means zero patches installed.
ReleaseId 1809 The version name. 1809 = October 2018 release. Useful as a search term. You can search "1809" or "Windows 10 1809" interchangeably with "Server 2019" since they share the same kernel.

Where to search and what to search for

MSRC
Microsoft MSRC Update Guide
Official Microsoft security advisories. Lists every CVE by Patch Tuesday date. Filter by: product = Server 2019, type = Elevation of Privilege. This is your primary source.
msrc.microsoft.com/update-guide
HIST
Server 2019 Update History
Maps every UBR to a KB article and release date. Use this to find your cutoff date from the UBR number. Bookmark this page.
support.microsoft.com → Windows Server 2019 update history
NVD
NVD — National Vulnerability DB
US government database. Every CVE has a CVSS score, description, affected versions, and links. Use to check severity (look for CVSS ≥ 7) and read technical details.
nvd.nist.gov/vuln/search
CVE
CVE Details — Server 2019
Aggregates all CVEs for Server 2019. Filter by type (Privilege Escalation), year, and CVSS score. Fast way to browse the full attack surface.
cvedetails.com → Windows Server 2019
GH
GitHub
Most PoC exploits are published here. Search by CVE number. Look for repos with recent commits and README files showing tested build versions.
github.com/search?q=CVE-XXXX-XXXXX+windows
EDB
Exploit-DB
Curated exploit database. Search by platform (Windows), type (Local), and CVE number. Has Metasploit modules and standalone PoC code ready to use.
exploit-db.com
PS
Packet Storm Security
Archive of exploits, advisories, and tools. Good for finding older PoCs and alternative implementations of known Windows CVEs.
packetstormsecurity.com
HT
HackTricks — Windows PrivEsc
Comprehensive community guide covering all known Windows privilege escalation techniques, CVEs, service abuses, and misconfigurations. Essential reference.
book.hacktricks.xyz → Windows local privilege escalation
PAT
PayloadsAllTheThings
Community cheat sheet of all Windows PrivEsc techniques and CVEs with PoC links. Great starting point for any engagement.
github.com/swisskyrepo/PayloadsAllTheThings
WES
WES-NG (Exploit Suggester)
Automated tool. Feed it your systeminfo output and it lists every unpatched CVE with exploit availability. The most efficient way to find missing patches.
github.com/bitsadmin/wesng

5

The full research workflow — step by step

1

Run the command and collect 4 values

Run the one command. Write down: ProductName, CurrentBuild, UBR, ReleaseId. Build your full version string: 17763.6893

Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion' |
  Select ProductName, CurrentBuild, UBR, ReleaseId
2

Find your exact patch date (your cutoff)

Search your full build on Microsoft's update history page. The date you get is your cutoff — everything patched after that date is still open on your system.

▶ 17763.6893 → KB5052000 → February 11, 2025 = your cutoff date
3

Find CVEs patched after your cutoff

Go to MSRC Update Guide. Filter: Product = Windows Server 2019, Type = Elevation of Privilege, Date = after your cutoff. Note every CVE number that appears.

⚠ Any CVE with patch date after Feb 11, 2025 = potentially vulnerable on this system
4

Check CVSS score and attack requirements

Look up each CVE on NVD. Focus on CVEs where: CVSS score ≥ 7, Attack Vector = Local, Privileges Required = Low. These are exploitable with only a normal user shell.

CVSS 9–10 = Critical CVSS 7–8 = High — focus here Local + Low priv = easiest
5

Search for a public PoC exploit

Search GitHub and Exploit-DB for the CVE number. Check the repo README to confirm it was tested on your build. A PoC tested on 17763.7136 works on 17763.6893 too since 6893 is older (less patched).

site:github.com CVE-2025-21204
6

Check PoC requirements before running

Every exploit has preconditions. Read the README carefully.

Question to askWhy it matters
Local or remote? Local = you need an existing shell on the target first. Remote = works over the network.
User level needed? Low = any normal user. Medium = needs some rights already (like a service account).
Which builds tested? If PoC says "tested on 17763.6893" = confirmed. If higher UBR = still likely works on yours.
Service required? Some exploits need Edge, Print Spooler, WMI, or specific services running.
7

Use automated tools to find more

Tools like WinPEAS and WES-NG scan automatically and list all unpatched CVEs based on your system info. Run these on every engagement.

.\winPEASx64.exe
python wesng.py --update
python wesng.py sysinfo.txt
